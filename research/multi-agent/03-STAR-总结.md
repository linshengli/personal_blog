# Multi Agent 技术 - STAR 总结

> 调研日期：2026-02-28

---

## STAR 方法论概述

STAR 是一种结构化总结方法，包含四个部分：
- **S**ituation（背景 + 痛点）
- **T**ask（核心问题）
- **A**ction（主流方案）
- **R**esult（效果 + 建议）

---

## Situation（背景 + 痛点）

**字数：约 150 字**

随着 LLM 应用场景复杂化，单个 Agent 面临能力边界限制：**复杂任务需要多步骤协作**、**专业领域需要专业知识**、**大规模问题需要并行处理**。传统 Single Agent 架构难以应对这些挑战，需要引入 Multi Agent 协作机制，通过角色分工和协同工作提升整体能力。

**核心痛点提炼**：
1. 单 Agent 能力边界有限
2. 复杂任务需要多领域专家
3. 需要交叉验证提升准确性
4. 大规模问题需要并行处理

---

## Task（核心问题）

**字数：约 100 字**

Multi Agent 系统需要解决的关键问题是：**如何在保证 Agent 自主性的同时，实现高效的协作和协调**。核心约束包括：通信效率（延迟<500ms）、任务分配公平性、冲突解决机制、系统可扩展性（支持 50+Agent）、人工监督接口。

**核心问题拆解**：
1. 通信效率 → 消息传递优化
2. 任务分配 → 负载均衡算法
3. 冲突解决 → 协商/投票机制
4. 可扩展性 → 分层架构设计

---

## Action（主流方案）

**字数：约 150 字**

技术演进历经三代：**第一代**（AutoGen）建立对话式多 Agent 基础；**第二代**（CrewAI/MetaGPT）引入角色和 SOP 提升结构化；**第三代**（LangGraph/AgentScope）支持状态持久化和多模态。核心突破包括：自然语言通信协议、基于角色的任务分配、辩论机制提升准确性、大规模社会模拟框架。

**技术演进关键点**：
| 代际 | 代表框架 | 核心贡献 | 局限性 |
|------|---------|---------|--------|
| 第一代 | AutoGen | 对话式协作 | 调试困难 |
| 第二代 | CrewAI/MetaGPT | 角色/SOP 结构化 | 灵活性降低 |
| 第三代 | LangGraph/AgentScope | 状态持久化/多模态 | 复杂度高 |

---

## Result（效果 + 建议）

**字数：约 100 字**

当前 Multi Agent 系统可提升任务完成率 30-50%，在软件开发、数据分析、创意创作等场景表现突出。但仍存在**通信开销大**、**调试困难**、**涌现行为不可预测**等挑战。实操建议：**研究用 AutoGen**，**原型用 CrewAI**，**软件开发用 MetaGPT**，**企业级用 LangGraph**，**游戏/仿真用 AgentScope**。

**核心指标**：
| 指标 | 当前水平 | 目标值 |
|------|---------|--------|
| 任务完成率 | 90%+ | 95%+ |
| 协作增益 | 30%+ | 50%+ |
| 通信开销 | <20% | <10% |

**选型建议速查**：
| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 研究实验 | AutoGen | 灵活，微软支持 |
| 快速原型 | CrewAI | 简洁，快速上手 |
| 软件开发 | MetaGPT | 领域专用，SOP 成熟 |
| 企业级 | LangGraph | 生态好，可维护 |
