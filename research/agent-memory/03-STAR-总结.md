# Agent Memory — STAR 总结

---

## Situation（背景 + 痛点）

LLM 天生是无状态的——每次请求都从零开始，不记得上一句话说了什么。随着 AI Agent 从简单问答演变为执行复杂多步骤任务的"数字员工"，这种"金鱼记忆"成为根本瓶颈：Agent 无法积累经验、无法个性化、无法在长期交互中保持一致性。虽然上下文窗口已扩展到百万级 token，但成本线性增长（128K 一次约 $0.1-0.5）、Lost-in-the-Middle 等问题意味着"暴力扩窗口"并非终极方案。

## Task（核心问题）

Agent Memory 需要解决三个核心挑战：**(1) 存什么**——从海量交互信息中筛选值得记忆的内容，避免噪声淹没有效信息；**(2) 怎么取**——在数百万条记忆中快速检索与当前任务最相关的少数几条，且延迟 <200ms；**(3) 何时忘**——在有限的存储和上下文预算内，智能地淘汰过时或低价值记忆。这三者的平衡构成了 Agent Memory 系统设计的核心张力。

## Action（主流方案 + 演进）

Agent Memory 经历了三个发展阶段：**2023 奠基期**，Stanford 的 Generative Agents 提出"记忆流+反思+规划"，MemGPT 引入类 OS 虚拟内存管理；**2024 工程化期**，Mem0 推出首个生产级通用记忆层（向量存储为主），Zep/Graphiti 开辟图谱记忆路线；**2025 系统化期**，MemoryOS 获 EMNLP Oral、混合架构（向量+图谱+压缩）成为共识、RL 驱动的自适应记忆管理开始萌芽。当前主流方案包括：纯上下文窗口（简单但贵）、向量数据库（主流平衡方案）、知识图谱（关系推理强）、层次化管理（最灵活）、混合架构（综合最优但复杂）。

## Result（效果 + 建议）

当前 SOTA 在 LoCoMo 基准上达到 ~92% 推理准确率（EverMemOS），但该基准的有效性存在争议——简单的全上下文基线就能达 73%。**实操建议**：快速原型选 Mem0（3 行代码集成），需要关系推理选 Zep/Graphiti，追求灵活性选 Letta，大型生产环境考虑混合架构。关注 2026 年 RL 驱动记忆管理和多模态记忆两个新方向。不要盲目追求基准分数，生产环境需综合评估延迟、成本和准确率。
