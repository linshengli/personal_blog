# AgentLoop 循环技术 - STAR 总结

> 调研日期：2026-02-28

---

## STAR 方法论概述

STAR 是一种结构化总结方法，包含四个部分：
- **S**ituation（背景 + 痛点）
- **T**ask（核心问题）
- **A**ction（主流方案）
- **R**esult（效果 + 建议）

---

## Situation（背景 + 痛点）

**字数：约 150 字**

LLM 本质上是单次推理模型，无法自主执行多步任务。要使 LLM 具备持续解决问题的能力，需要建立循环执行机制。但设计 AgentLoop 面临多重挑战：**如何平衡循环次数与效果**、**如何设计合理的终止条件**、**如何处理执行中的错误**、**如何优化 Token 消耗**。

**核心痛点提炼**：
1. LLM 单次推理无法完成复杂任务
2. 循环次数与效果需要平衡
3. 终止条件设计困难
4. Token 成本优化需求

---

## Task（核心问题）

**字数：约 100 字**

AgentLoop 需要解决的关键问题是：**如何设计高效、可靠、可控的循环执行机制，使 Agent 能够自主完成复杂的多步任务**。核心约束包括：循环效率（平均<8 次）、单次延迟（<2s）、错误恢复率（>70%）、Token 成本控制。

**核心问题拆解**：
1. 循环效率 → 减少冗余循环
2. 终止条件 → 完成/超时/中断判断
3. 错误处理 → 重试/恢复机制
4. 成本控制 → Token 用量优化

---

## Action（主流方案）

**字数：约 150 字**

技术演进历经三代：**第一代**（ReAct）建立推理 - 行动交替执行范式；**第二代**（Reflexion/Self-RAG）引入自我反思和自适应机制；**第三代**（LangGraph/事件驱动）支持精确编排和并发执行。核心突破包括：ReAct 范式、反思学习机制、状态图编排、异步并发模型。

**技术演进关键点**：
| 代际 | 代表技术 | 核心贡献 | 局限性 |
|------|---------|---------|--------|
| 第一代 | ReAct | 推理 - 行动交替 | 效率低 |
| 第二代 | Reflexion/Self-RAG | 反思学习 | 实现复杂 |
| 第三代 | LangGraph/事件驱动 | 精确编排/并发 | 学习曲线陡 |

---

## Result（效果 + 建议）

**字数：约 100 字**

当前 AgentLoop 技术可支持 85%+ 的任务完成率，平均循环 3-8 次，单次延迟<2s。但仍存在**冗余循环多**、**错误恢复有限**、**成本高**等挑战。实操建议：**原型用 ReAct**，**结构化任务用 Plan-and-Execute**，**学习型用 Reflexion**，**企业级用 LangGraph**。

**核心指标**：
| 指标 | 当前水平 | 目标值 |
|------|---------|--------|
| 任务完成率 | 85%+ | 95%+ |
| 平均循环次数 | 3-8 次 | 2-5 次 |
| 单次延迟 | <2s | <1s |

**选型建议速查**：
| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 快速原型 | ReAct | 简单快速 |
| 结构化任务 | Plan-and-Execute | 全局规划 |
| 学习型 | Reflexion | 持续改进 |
| 企业级 | LangGraph | 精确可控 |
