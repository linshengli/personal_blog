## 1. 概念剖析

### 1.1 什么是 Agent Sandbox

**Agent Sandbox（智能体沙箱）** 是一种为 AI Agent 提供安全执行环境的隔离机制。它允许 Agent 在受限的环境中执行代码、调用工具、访问资源，同时防止对宿主系统造成潜在损害。

### 1.2 为什么需要沙箱

AI Agent 在执行任务时可能涉及以下风险：

| 风险类型 | 描述 | 示例 |
|---------|------|------|
| 代码执行风险 | Agent 生成或执行的代码可能有害 | 恶意代码、无限循环、资源耗尽 |
| 数据泄露风险 | Agent 可能访问敏感数据 | 读取凭证文件、数据库泄露 |
| 系统破坏风险 | Agent 可能修改或删除系统文件 | 误删关键文件、配置错误 |
| 网络攻击风险 | Agent 可能被利用进行网络攻击 | DDoS 攻击、未授权访问 |
| 权限提升风险 | Agent 可能获取超出预期的权限 | 提权漏洞利用 |

### 1.3 沙箱的核心目标

```
┌─────────────────────────────────────────────────────────┐
│                   Agent Sandbox Goals                    │
├─────────────────────────────────────────────────────────┤
│  • Isolation    - 与宿主系统完全隔离                     │
│  • Containment  - 限制资源使用和访问范围                  │
│  • Monitoring   - 监控所有操作行为                        │
│  • Recovery     - 快速恢复和回滚能力                      │
└─────────────────────────────────────────────────────────┘
```

## 2. 主流沙箱方案

### 2.1 Docker 容器沙箱

**特点：**
- 基于 Linux 容器技术
- 提供进程、网络、文件系统隔离
- 轻量级，启动快速

**架构图：**
```
┌─────────────────────────────────────────────┐
│              Host System                     │
│  ┌───────────────────────────────────────┐  │
│  │         Docker Daemon                  │  │
│  │  ┌─────────────┐ ┌─────────────┐      │  │
│  │  │  Container  │ │  Container  │      │  │
│  │  │  (Agent A)  │ │  (Agent B)  │      │  │
│  │  │  ┌───────┐  │ │  ┌───────┐  │      │  │
│  │  │  │ Limit │  │ │  │ Limit │  │      │  │
│  │  │  │ CPU   │  │ │  │ CPU   │  │      │  │
│  │  │  │ Memory│  │ │  │ Memory│  │      │  │
│  │  │  └───────┘  │ │  └───────┘  │      │  │
│  │  └─────────────┘ └─────────────┘      │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

**示例配置：**
```yaml
version: '3.8'
services:
  agent-sandbox:
    image: python:3.11-slim
    mem_limit: 512m
    cpus: 0.5
    read_only: true
    tmpfs:
      - /tmp
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges
```

### 2.2 gVisor

**特点：**
- Google 开发的沙箱容器运行时
- 用户空间内核实现
- 提供比 Docker 更强的隔离

**架构：**
```
┌─────────────────────────────────────────────────┐

├─────────────────────────────────────────────────┤
│                Sentry (用户空间内核)              │

│  • 文件系统访问代理                               │
├─────────────────────────────────────────────────┤
│                Host Kernel                       │
└─────────────────────────────────────────────────┘
```

### 2.3 Firecracker MicroVM

**特点：**
- AWS 开发的轻量级虚拟机
- 基于 KVM 硬件虚拟化
- 启动时间 < 125ms

**对比：**
| 方案 | 启动时间 | 内存开销 | 隔离级别 |
|------|---------|---------|---------|
| Docker | ~1s | ~5MB | 容器级 |
| gVisor | ~1s | ~10MB | 增强容器 |
| Firecracker | <125ms | ~5MB | VM 级 |

### 2.4 WASM 沙箱

**特点：**
- WebAssembly 运行时隔离
- 跨平台支持
- 细粒度权限控制

**示例 - Wasmtime 配置：**
```rust
use wasmtime::*;

let mut store = Store::default();
let module = Module::from_file(store.engine(), "agent.wasm");

// 配置资源限制
let mut limiter = ResourceLimiter::default();
limiter.memory_size(1024); // 最大 1GB 内存
limiter.table_size(10000); // 最大表大小

store.limiter(&mut limiter);
```

| 方案 | 类型 | 特点 | 适用场景 |

## 3. 安全隔离机制

### 3.1 文件系统隔离

**策略：**
```
┌─────────────────────────────────────────┐
│           文件系统隔离层次                │
├─────────────────────────────────────────┤
│ Level 1: 只读根文件系统                  │
│ Level 2: 临时目录挂载 (tmpfs)            │
│ Level 3: 白名单目录访问                  │
│ Level 4: 虚拟文件系统抽象                │
└─────────────────────────────────────────┘
```

**实现示例：**
```python
# 使用 Python 的 pathlib 实现受限文件访问
from pathlib import Path
import os

class SandboxedPath:
    def __init__(self, root_dir, allowed_dirs):
        self.root = Path(root_dir).resolve()
        self.allowed = [Path(d).resolve() for d in allowed_dirs]

    def safe_open(self, path, mode='r'):
        full_path = (self.root / path).resolve()

        # 路径遍历检查
        if not str(full_path).startswith(str(self.root)):
            raise SecurityError("Path traversal detected")

        # 白名单检查
        if not any(str(full_path).startswith(str(d)) for d in self.allowed):
            raise SecurityError("Access denied")

        return open(full_path, mode)
```

### 3.2 网络隔离

**网络隔离策略：**

| 级别 | 描述 | 配置示例 |
|------|------|---------|
| 完全隔离 | 无网络访问 | `--network none` |
| 出站限制 | 仅允许特定出站 | 防火墙规则 |
| 域名白名单 | 仅允许访问特定域名 | DNS 过滤 |
| 代理模式 | 通过代理访问 | HTTP_PROXY |

**Docker 网络隔离示例：**
```bash
# 创建隔离网络
docker network create --driver bridge \
  --opt com.docker.network.bridge.enable_ip_masquerade=false \
  agent-network

# 限制容器只能访问特定服务
docker run --network agent-network \
  --network-alias allowed-service \
  agent-container
```

## 4. 执行环境

### 4.1 代码执行沙箱

**Python 代码执行沙箱示例：**
```python
import ast
import sys
from types import ModuleType

class SafeInterpreter:
    """安全的 Python 代码解释器"""

    DANGEROUS_BUILTINS = {
        '__import__', 'eval', 'exec', 'compile',
        'open', 'input', 'breakpoint'
    }

    def __init__(self):
        self.safe_globals = self._build_safe_globals()

    def _build_safe_globals(self):
        safe_dict = {}
        for name in dir(__builtins__):
            if name not in self.DANGEROUS_BUILTINS:
                if name == 'print':
                    safe_dict[name] = self._safe_print
                else:
                    obj = getattr(__builtins__, name)
                    if isinstance(obj, ModuleType):
                        safe_dict[name] = obj
                    elif callable(obj):
                        safe_dict[name] = obj
        return safe_dict

    def _safe_print(self, *args, **kwargs):
        # 限制输出大小
        output = ' '.join(str(a) for a in args)
        if len(output) > 10000:
            raise SecurityError("Output too large")
        print(output[:10000])

    def execute(self, code: str, timeout: int = 5):
        # AST 安全检查
        tree = ast.parse(code)
        self._check_ast(tree)

        # 执行
        exec(compile(tree, '<sandbox>', 'exec'),
             self.safe_globals, {})

    def _check_ast(self, node):
        for child in ast.iter_child_nodes(node):
            if isinstance(child, ast.Import):
                raise SecurityError("Import not allowed")
            self._check_ast(child)
```

### 4.3 超时与终止机制

```python
import signal
from contextlib import contextmanager

class TimeoutError(Exception):
    pass

@contextmanager
def timeout(seconds: int):
    """执行超时保护"""
    def handler(signum, frame):
        raise TimeoutError(f"Execution timed out after {seconds}s")

    old_handler = signal.signal(signal.SIGALRM, handler)
    signal.alarm(seconds)

    try:
        yield
    finally:
        signal.alarm(0)
        signal.signal(signal.SIGALRM, old_handler)

# 使用示例
try:
    with timeout(30):
        agent.execute()
except TimeoutError as e:
    logger.error(f"Agent execution terminated: {e}")
```

| 方案 | 启动时间 | CPU 开销 | 内存开销 | 系统调用延迟 |
|------|---------|---------|---------|-------------|
| 原生执行 | ~0ms | 1x | 1x | 1x |

### 5.2 安全级别对比

```
安全级别 (低 → 高)
│
├─ Docker (基本隔离)
│    └── 适合：可信 Agent、内部测试
│
├─ gVisor (增强隔离)
│    └── 适合：多租户、生产环境
│
├─ Firecracker (VM 级隔离)
│    └── 适合：高安全需求、不可信代码
│
└─ 专用硬件隔离 (最高级别)
     └── 适合：金融、医疗等敏感场景
```

### 5.3 选择建议

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 开发测试 | Docker | 快速迭代、资源消耗低 |
| 生产环境 | gVisor/Kata | 平衡安全与性能 |
| 不可信代码 | Firecracker | VM 级隔离保障 |
| 边缘计算 | WASM | 轻量级、跨平台 |

### 6.1 E2B (Sandbox for AI Code Execution)

**特点：**
- 专为 AI Agent 设计的沙箱环境
- 支持 Python、Node.js 等多种运行时
- 提供文件系统和网络访问控制

**使用示例：**
```python
from e2b import Sandbox

sandbox = Sandbox(template="python3")
execution = sandbox.run_code("print('Hello from sandbox!')")
print(execution.logs.stdout)

# 文件操作
sandbox.files.write("/data/test.txt", "content")
content = sandbox.files.read("/data/test.txt")
```

### 6.3 GitHub Copilot Workspace

**沙箱策略：**

### 6.4 自定义实现示例

```python
import docker
import asyncio
from typing import Optional

class AgentSandbox:
    def __init__(self, image: str = "python:3.11-slim"):
        self.client = docker.from_client()
        self.image = image
        self.container: Optional[docker.Container] = None

    async def create(self, memory_limit: str = "512m",
                     cpu_limit: float = 0.5):
        """创建沙箱容器"""
        self.container = self.client.containers.run(
            self.image,
            command="tail -f /dev/null",
            detach=True,
            mem_limit=memory_limit,
            nano_cpus=int(cpu_limit * 1e9),
            read_only=True,
            tmpfs={"/tmp": "rw,noexec,nosuid,size=64m"},
            cap_drop=["ALL"],
            security_opt=["no-new-privileges"],
            network_disabled=True,
        )
        return self

    async def execute(self, code: str, timeout: int = 30):
        """执行代码"""
        if not self.container:
            raise RuntimeError("Sandbox not created")

        # 写入代码
        self.container.put_archive(
            "/sandbox",
            self._create_tar(code)
        )

        # 执行
        result = self.container.exec_run(
            "python /sandbox/code.py",
            demux=True,
            stdout=True,
            stderr=True,
        )

        return {
            "stdout": result.output[0].decode(),
            "stderr": result.output[1].decode(),
            "exit_code": result.exit_code
        }

    async def destroy(self):
        """销毁沙箱"""
        if self.container:
            self.container.remove(force=True)
            self.container = None
```
